# 立場的時間與變化

「各方現在說什麼」與「同一對象如何改變」是兩個閱讀任務。positions_debate 必須交代觀察期間、逐時主張及可判斷的變化範圍。position_evolution 是核心角色，即使資料不足也要明說無法判定。

先以 issue（議題背景與共同問題）交代必要前情、制度／提案內容、爭議起點及範圍，讓讀者知道各方在爭什麼，再開始逐筆主張與時間比較。背景短而有來源即可；未提供起因時明示，不能從某方說法自行重建成確定事實。

## 逐筆記錄

對立場材料的 claim 加上 position：

| 欄位 | 意義 |
| --- | --- |
| stakeholder_id / stakeholder_name | 穩定 ID 與一致的對象名稱 |
| identity_basis | 用什麼來源確認身分或代表關係；不能只憑同名合併 |
| issue_id / issue | 可比較的爭點 ID 與明確範圍 |
| statement_date | 實際發言／聲明日期，可年、月、日；未知為 null |
| context | 發言身分、場合、方案版本與相關語境 |
| stance | 帶條件的主張摘要，不強制支持／反對二分 |
| conditions / reasons | 主張條件與理由；未提供時用空陣列，不自行推測 |

claim.speaker 保留實際發言者；stakeholder 是這筆主張所歸屬的對象。例如發言人代組織正式發言可歸該組織，但要記錄代表依據；個人觀點另用個人 ID。人物換職位、組織換發言人或名稱改變，都須回查歸屬，不自動合併或拆分。

每筆 claim.refs 指向原始片段。文章發布日不是發言日，回顧報導也不能當成新的表態。同一說法被多篇轉載不構成多個時間點。未知日期不得用刊出日代填。

## 比較判斷

至少兩筆同 stakeholder、同爭點的 positioned claims 才建立 stance_comparison。claim_ids 保留逐筆來源，refs 包含所有被比較 claims 的來源。這是有依據的分析結果，不是來源自行宣告的事實；text 明說依哪些說法、在何範圍內得出判斷。

- changed：在可比較的問題與條件下，主張出現實質改變；具體說明改變什麼。
- consistent：已取得的不同時點說法一致；只能說這些時點一致，不推定其間從未改變。
- conditional：表述差異主要涉及條件、理由或適用範圍；交代差異，不直接稱為立場逆轉。
- not_comparable：方案版本、議題含義或發言語境不足以直接比較；說明原因。
- insufficient：有多筆說法，但時間、內容或可比性不足以判斷。

前三種需依時間排序，日期區間不得重疊。若僅知「2024年」與「2024年6月」，不能由此確定先後；保留原精度並標 insufficient 或改以文字列出限制。一天內的說法若只有日期而無可驗證順序，也不推定先後；目前契約只支援年至日精度。

只有單一主張時不要建立虛假的比較證據。position_evolution 可標 partial（已知單一立場，但缺後續）或 missing（必要材料皆缺），並交代無法判斷變化。沒有表態不代表立場不變，最新檢索紀錄也不等於截至今天的現行立場。

## 呈現與限制

優先以 stakeholder × 時間的比較表呈現主張、理由、條件與來源。時間軸只在已有相關且具可靠日期的 event 證據時使用；claim 不直接冒充 event。文字仍交代語境與比較判斷。

程式驗證可檢查 ID、日期、來源與引用一致性，不能證明人物確為同一人，或兩句話真的構成立場改變。這些必須回查來源並做語意檢核。
