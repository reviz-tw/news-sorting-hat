# 回答類型庫 v0.1

分類對象是本次回答，參考問題與取得的新聞片段；不是文章主題或圖表類型。主要類型一個，次類型不重複、不含主要類型；選擇確實支撐回答的類型即可。

| ID | 類型／閱讀任務 | 必須保留 | 常見邊界 |
| --- | --- | --- | --- |
| event_brief | 事件事實敘述：發生什麼？ | 人、事、時、地、相關對象、已知結果；必要時收尾補其他說法與回應 | 相關說法帶歸屬；不補造反方，核心爭議或更正也須反映於開頭 |
| human_story | 人物與經驗敘事：處境與選擇？ | 先介紹人物背景與當時處境，再交代經歷、選擇、原話與限制，有相關側訪時收尾補他人觀察 | 側訪帶關係與依據，不強配正反；背景只取故事所需，不由身分推定動機；不把個人經驗當全體統計 |
| event_context | 事件脈絡與重建：如何走到這裡？ | 關鍵事件、時間、參與者、轉折與疑點；收尾補相關其他方觀點 | 有先後不代表有因果；觀點帶歸屬，關鍵分歧同步標於經過與轉折 |
| issue_explainer | 議題與機制解釋：是什麼、如何運作、各方如何理解？ | 概念、背景、機制、相關法規與法律見解、不同觀點與理由、範圍與例外 | 區分規範與評論，保留法域及版本；缺依據就明示，不補造對立或法條 |
| positions_debate | 立場與爭點分析：各方何時主張什麼，同一對象是否改變？ | 先交代議題背景、爭議起點與共同問題，再整理 stakeholder 身分、觀察期間、逐時主張、理由、條件、證據與變化 | 不強分正反；不把措辭、版本差異或沉默當成立場轉向／不變 |
| data_analysis | 資料現況與趨勢：發現什麼、規模與差異有何意義？ | 核心洞察先行，接既有認識與新發現的對照，再展開數據、口徑與限制；資料足夠時搭配一至多張圖表 | 數據為核心問題才作主類型；不為洞察誇大因果，不為圖表補造數據 |
| comparative_analysis | 對象與方案比較：同異及意義？ | 對象、共同維度、基準、比較表與差異解讀、不可比之處 | 不強行量化質性差異；區分未知、不適用與不可比 |
| accountability | 調查揭露與問責：脈絡、發現、落差及責任？ | 必要背景與調查摘要先行，再交代問題線索、落差與質疑，展開證據、權責、當事方回應、未解處 | 區分事實與指控，不預斷責任；缺少背景或回應要揭露，不補寫 |
| discourse_analysis | 輿論與媒體敘事：如何談論，分析發現什麼？ | 文本來源、樣本、群體、框架、方法、分析結果與例句／數據對照、適當視覺化 | 不從摘錄推全體頻率或支持比例；區分質性編碼與量化統計 |
| impact_scenarios | 影響、風險與情境：對誰、什麼條件？ | 受影響者、途徑、期間、假設、不確定性 | 區分已發生影響與未來情境 |
| policy_evaluation | 政策執行與成效：承諾做到嗎？ | 目標、措施、投入、進度、成果、評估限制 | 目標不等於預測；前後差異不等於政策效果 |
| claim_verification | 說法查證與證據釐清：支持程度？ | 先交代事件緣由與查證背景，再列待查說法、提出者、支持／反對證據與判定範圍 | 背景也需來源，待查事件保留歸屬；不強迫真假二分 |

分類庫目前保留 12 類，暫不設獨立的服務資訊／申辦行動指引類型。新聞中的資格、期限或步驟可依實際閱讀任務保留在適合類型的段落；不能只因移除類型就強制改成事件敘述。無法歸入保留類型時，依契約使用 undetermined、primary=null 與 unclassified 結構。

以主要閱讀任務判斷重疊：檢驗承諾與結果以 policy_evaluation 為主；追查責任與異常以 accountability 為主；當事人遭遇若只是背景，human_story 不必成為次類型。

例如，只問「何時宣布停辦」用 event_brief；問「制度為何保護不了師生」可能用 issue_explainer + accountability。來源是調查專題，也不改變前者的簡答任務。

另用 tags 保留四個獨立軸：topic（教育、交通）、method（訪談、文件比對、統計）、angle（權利保障、空間差異）、temporal（歷史回顧、事件當時、未來情境）。這些不增加主要類型。
